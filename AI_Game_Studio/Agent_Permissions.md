# AI Game Studio Agent 权限管理规范

**文件名称：** Agent_Permissions.md

**工作室名称：** AI Game Studio

**当前版本：** 1.0

**文件性质：** 工作室核心固定规则

**适用范围：** 所有 Agent、所有游戏项目

**最高权限持有者：** 人类管理者

---

## 1. 文件目的

本文件用于明确 AI Game Studio 中不同 Agent 的权限范围，防止 Agent 越权操作、修改不属于自己职责范围的文件，或者擅自改变工作室和游戏项目的管理规则。

所有 Agent 必须遵守本文件。

本文件与 Studio_Guide.md、Terminology.md 共同构成工作室核心规则。

当 Agent 不确定自己是否拥有某项操作权限时，必须先确认权限，不得默认自己拥有权限。

---

## 2. 权限管理基本原则

### 2.1 人类管理者拥有最高权限

人类管理者拥有工作室的最高决策权和最终授权权。

人类管理者可以：

- 修改任何工作室固定规则。
- 调整任何 Agent 的职责。
- 授予或收回 Agent 权限。
- 修改游戏项目目标。
- 批准重大技术和策划方案。
- 决定是否接受、退回或取消某项工作成果。

任何 Agent 的权限都不得高于人类管理者。

### 2.2 最小权限原则

每个 Agent 只获得完成自身职责所需要的权限。

不得因为某个 Agent 能够访问某个目录，就认为它可以修改该目录中的所有文件。

读取权限与修改权限必须分别判断。

### 2.3 职责与权限对应原则

每个 Agent 的操作权限必须与其角色职责相对应。

例如：

- 游戏策划 Agent 负责游戏策划，因此拥有策划资料的维护权限。
- 主程 Agent 负责技术规划和开发调度，因此拥有技术规划和开发任务管理权限。
- 模块开发 Agent 负责具体开发，因此只能修改当前任务授权的工程文件。

### 2.4 未授权操作禁止原则

如果 Agent 需要执行的操作超出自身权限，必须：

1. 暂停该操作。
2. 说明需要执行的操作。
3. 说明为什么需要该权限。
4. 向总控 Agent 或人类管理者提出申请。
5. 获得明确授权后再执行。

不得通过其他文件、其他 Agent 或其他对话间接绕过权限限制。

## 3. 工作室固定规则的权限

工作室固定规则包括：

- Studio_Guide.md
- Terminology.md
- Agent_Permissions.md
- File_Management_Rules.md
- Task_Management_Rules.md
- Handoff_Rules.md
- Agents/ 目录下的角色定义文件
- Templates/ 目录下的工作模板

### 3.1 总控 Agent 的权限

总控 Agent 可以：

- 阅读全部工作室固定规则。
- 检查规则是否存在冲突或不合理之处。
- 根据实际项目经验提出规则修改建议。
- 向人类管理者说明修改原因、影响范围和建议内容。
- 在获得人类管理者明确确认后，执行获批的规则修改。
- 记录规则修改历史。

总控 Agent 不得：

- 未经确认直接修改固定规则。
- 擅自增加、删除或调整其他 Agent 的权限。
- 擅自改变自身或其他 Agent 的职责。
- 将自己提出的建议视为已经获得批准。
- 以项目开发需要为理由绕过固定规则修改流程。

### 3.2 游戏策划 Agent 的权限

游戏策划 Agent 可以：

- 阅读工作室固定规则。
- 阅读自己的角色定义。
- 提出与策划工作有关的规则优化建议。

游戏策划 Agent 不得：

- 修改工作室固定规则。
- 修改任何 Agent 的角色定义。
- 修改 Agent 权限。
- 修改工作室模板。
- 将自己的项目策划权限扩大为工作室规则管理权限。

### 3.3 主程 Agent 的权限

主程 Agent 可以：

- 阅读全部工作室固定规则。
- 检查规则是否影响技术规划和开发流程。
- 提出技术管理和开发流程方面的规则修改建议。

主程 Agent 不得：

- 未经确认修改固定规则。
- 擅自调整模块开发 Agent 的基础权限。
- 擅自修改文件锁定规则。
- 擅自修改自身或其他 Agent 的角色定义。

### 3.4 模块开发 Agent 的权限

模块开发 Agent 只能读取与当前任务有关的工作室规则和角色规范。

模块开发 Agent 不得修改任何工作室固定规则。

### 3.5 代码审核 Agent 的权限

代码审核 Agent（Code Reviewer Agent）在工作室固定规则方面的权限：

- 可以阅读全部工作室固定规则。
- 可以阅读自己的角色定义文件。
- 可以提出代码审核流程相关的规则优化建议。
- 不得修改任何工作室固定规则。
- 不得修改任何 Agent 的角色定义。
- 不得修改 Agent 权限。

## 4. Terminology.md 术语词典的特殊权限

Terminology.md 是全工作室统一使用的术语词典。

它与其他固定规则不同：允许指定的专业 Agent 在遵守规定的情况下主动增加新术语。

### 4.1 允许维护词典的 Agent

以下 Agent 可以提出并登记新术语：

- 总控 Agent。
- 游戏策划 Agent。
- 主程 Agent。

模块开发 Agent 默认没有直接修改术语词典的权限。

模块开发 Agent 发现需要新术语时，应向主程 Agent 提交术语建议。

### 4.2 新增术语权限

总控、游戏策划和主程 Agent 可以在以下条件全部满足时新增术语：

1. 已检查现有词典。
2. 确认没有合适的现有术语。
3. 新术语具有明确的实际用途。
4. 已填写中文名称、英文名称、缩写、准确含义和使用示例。
5. 已检查是否与现有术语重复或冲突。

满足上述条件后，可以直接更新 Terminology.md，不需要逐个术语向人类管理者申请。

新增术语后，必须检查文件保存结果并更新术语变更记录。

### 4.3 修改已有术语权限

新增术语与修改已有术语必须严格区分。

对于已经正式收录的术语：

- 修改含义：必须由总控提出建议并取得人类管理者确认。
- 修改标准缩写：必须由总控提出建议并取得人类管理者确认。
- 废弃术语：必须由总控提出建议并取得人类管理者确认。
- 删除正式术语：原则上不允许直接删除，应保留历史记录并标注废弃状态。

不得因为某个 Agent 更习惯另一种说法，就随意改变现有术语的定义。

## 5. 游戏项目资料的权限

每个游戏项目都有独立的项目资料目录。

默认采用以下目录：

AI_Project/

- Project_Overview.md
- Current_Status.md
- Designer/
- Technical/
- Development/
- Handoffs/
- Reviews/
- Logs/

### 5.1 总控 Agent 的项目资料权限

总控 Agent 可以：

- 阅读全部项目资料。
- 维护 Project_Overview.md。
- 维护 Current_Status.md。
- 维护项目变更记录。
- 维护 Agent 重要活动记录。
- 创建项目管理所需的文件。
- 审核其他 Agent 提交的项目资料。
- 提出项目资料的修改建议。
- 在职责范围内修改管理类项目文件。

总控 Agent 不得：

- 未经确认擅自改变已经批准的核心游戏设计。
- 随意覆盖策划 Agent 的原始策划成果。
- 擅自修改主程 Agent 正在维护的技术规划。
- 代替主程 Agent 分配工程文件修改权。
- 未经审核直接将开发任务标记为完成。

### 5.2 游戏策划 Agent 的项目资料权限

游戏策划 Agent 可以：

- 阅读项目基本信息。
- 阅读当前项目进度。
- 阅读与策划有关的技术限制。
- 创建策划文档。
- 修改自己负责的策划文档。
- 删除不再需要的策划文档。
- 根据用户和总控的反馈更新设计内容。
- 将策划成果交付给总控和主程 Agent。

游戏策划 Agent 的主要写入范围：

Designer/

包括：

- Game_Design.md
- Gameplay/
- Characters/
- Levels/
- UI_UX/

游戏策划 Agent 不得：

- 修改 Current_Status.md。
- 修改主程负责的技术规划。
- 修改开发任务和文件锁定记录。
- 直接修改 UE5 工程代码。
- 擅自改变已经批准的核心设计方向。

如果策划 Agent 发现技术方案需要调整，应将需求提交给主程 Agent，而不是直接修改技术文件。

### 5.3 主程 Agent 的项目资料权限

主程 Agent 可以：

- 阅读全部项目资料。
- 阅读和检查真实 UE5 工程。
- 创建技术规划文档。
- 修改自己负责的技术文档。
- 创建开发任务。
- 修改任务状态和任务内容。
- 维护开发任务清单。
- 维护文件锁定记录。
- 管理任务依赖关系。
- 审核模块开发 Agent 的技术交付。

主程 Agent 的主要写入范围：

- Technical/
- Development/

主程 Agent 不得：

- 擅自修改工作室固定规则。
- 随意修改策划 Agent 的原始设计文档。
- 修改 Current_Status.md 的权威项目进度内容。
- 绕过文件锁定规则。
- 将未经过审核的开发成果直接标记为正式完成。

如果主程认为策划方案存在技术问题，应将问题反馈给策划 Agent 或总控 Agent。

### 5.4 模块开发 Agent 的项目资料权限

模块开发 Agent 可以：

- 阅读项目基本信息。
- 阅读当前项目进度。
- 阅读当前任务单。
- 阅读相关技术架构和策划资料。
- 创建自己的交付报告。
- 在授权范围内更新自己的开发记录。

模块开发 Agent 的写入范围：

- 当前任务授权的交付报告。
- 当前任务明确允许修改的其他项目资料。

模块开发 Agent 不得：

- 修改策划 Agent 负责的策划文件。
- 修改主程 Agent 的技术架构文档。
- 修改其他任务的任务单。
- 修改文件锁定记录。
- 修改 Current_Status.md。
- 擅自创建新的开发任务。
- 擅自释放文件锁。

### 5.5 代码审核 Agent 的项目资料权限

代码审核 Agent 可以：

- 阅读全部项目资料。
- 阅读与当前审核有关的任务单、技术文档和策划文档。
- 阅读模块开发 Agent 的交付报告。
- 阅读 File_Lock_Register.md（了解当前锁定状态）。
- 创建和维护 `Reviews/Code_Reviews/` 下的代码审核报告。
- 在审核报告中记录实际检查的文件和内容。

代码审核 Agent 的**唯一写入范围**：

```
AI_Project/Reviews/Code_Reviews/
```

代码审核 Agent 不得：

- 修改策划 Agent 负责的策划文件。
- 修改主程 Agent 的技术架构文档。
- 修改任务单、文件锁定记录或其他开发管理文件。
- 修改 Current_Status.md。
- 修改 Project_Overview.md。
- 修改 UE5 工程文件。
- 擅自创建新的开发任务。
- 擅自释放文件锁。
- 直接给模块开发 Agent 下达返工指令。
- 代替主程执行最终技术验收。

**关键权限约束：** 代码审核 Agent 是只读的独立审核者。它不能直接修改任何工程文件，不能直接分配任务，不能直接管理文件锁定。它的唯一正式输出是 Markdown 格式的代码审核报告，由主程 Agent 接收并据此决定后续处理方式。

## 6. UE5 工程文件的权限

UE5 工程文件包括但不限于：

- Source/
- Content/
- Config/
- Plugins/
- 项目配置文件。
- 其他实际工程资源。

### 6.1 总控 Agent

默认只拥有读取权限。

除非人类管理者明确授权，否则不得直接修改工程文件。

### 6.2 游戏策划 Agent

默认只拥有读取与设计工作有关的工程信息的权限。

不得直接修改工程代码、蓝图或其他工程资源。

### 6.3 主程 Agent

拥有工程检查、技术分析和任务规划权限。

主程可以根据具体任务获得工程文件修改权限。

但必须遵守文件锁定规则，不得在其他任务已经锁定文件时直接修改。

如果主程需要亲自开发，也必须按照开发任务的授权流程执行。

### 6.4 模块开发 Agent

只允许修改当前任务单中明确列出的工程文件。

如果开发过程中发现需要修改额外文件：

1. 暂停对额外文件的修改。
2. 向主程 Agent 提交修改申请。
3. 说明修改原因和预期影响。
4. 等待主程检查文件冲突并批准。
5. 主程更新任务单和文件锁定记录后，才能继续修改。

不得通过修改其他文件绕过当前任务的授权范围。

### 6.5 代码审核 Agent

代码审核 Agent 对 UE5 工程文件**默认只有读取权限**。

- 可以读取与当前审核有关的全部工程文件。
- 可以读取任务单中列出的允许修改文件。
- 可以检查实际代码变更是否在授权范围内。
- **绝对不得修改**任何 UE5 工程文件。

代码审核 Agent 的审核工作基于只读检查。如果需要确认编译结果或运行时行为，应通过模块开发 Agent 的交付报告获取证据，不得自行修改工程来验证。

## 7. 文件创建、修改与删除权限

文件操作分为三类：

### 7.1 创建文件

Agent 只有在以下条件满足时才能创建文件：

- 文件属于自己的职责范围。
- 文件目录符合项目结构规范。
- 不与现有文件重复。
- 创建行为没有超出当前任务或管理职责。

### 7.2 修改文件

Agent 修改文件前必须：

1. 确认文件属于自己的权限范围。
2. 读取文件当前内容。
3. 确认没有其他任务正在锁定该文件。
4. 确认修改不会覆盖其他 Agent 尚未审核的成果。
5. 完成修改后检查保存结果。

### 7.3 删除文件

删除文件属于高风险操作。

必须遵守：

- 不得删除其他 Agent 负责的文件。
- 不得删除已经批准的核心项目文档。
- 不得删除工作室固定规则。
- 删除文件前必须确认文件已经不再需要。
- 对重要文件，优先采用标记废弃或移动归档的方式，而不是直接删除。

如果无法确认文件是否可以删除，必须请求总控或人类管理者确认。

## 8. 权限变更机制

任何涉及 Agent 职责和权限的调整，都属于工作室规则变更。

统一流程：

1. Agent 发现现有权限不满足实际工作需求。
2. 向总控 Agent 提出权限调整建议。
3. 总控 Agent 分析修改原因、影响范围和风险。
4. 总控 Agent 将建议提交给人类管理者。
5. 人类管理者明确批准或拒绝。
6. 获得批准后，总控 Agent 更新 Agent_Permissions.md 和相关角色定义文件。
7. 总控 Agent 检查所有相关文件是否同步更新。
8. 记录本次权限变更。

未经人类管理者明确确认，任何权限变更均不生效。

---

## 9. 权限冲突处理

如果两个 Agent 对某项文件或操作权限存在争议：

1. 暂停有争议的修改操作。
2. 检查本文件中的权限规定。
3. 由总控 Agent 判断是否属于正常职责划分问题。
4. 如果涉及固定规则变更，提交人类管理者确认。
5. 解决冲突后再恢复工作。

任何 Agent 不得通过抢先修改文件的方式获得实际控制权。

---

## 10. 权限执行与技术限制

本文件定义的是工作室内部的操作授权规则。

Agent 必须遵守这些规则，但需要明确：

1. 文件权限规则本身不等于操作系统文件权限。
2. 如果某个 Agent 在技术上拥有整个目录的写入权限，仍可能发生误操作。
3. 多 Agent 并发访问时，必须结合任务级文件锁定、Git 分支或独立工作区等机制降低风险。
4. 如果平台无法提供物理只读保护，Agent 必须通过明确的操作约束遵守本文件。
5. 发现越权修改时，必须停止相关操作并向总控报告。

---

## 11. 权限规范优先级

权限判断按照以下顺序执行：

1. 人类管理者最新的明确指令。
2. 经人类管理者确认的工作室固定规则。
3. 本文件规定的 Agent 权限。
4. 对应 Agent 的角色定义。
5. 当前项目的具体授权。
6. Agent 自行提出的建议。

如果不同规则之间存在无法解决的冲突，必须暂停相关操作并请求人类管理者确认。
